### Step 1: 실패 시나리오 정의 (Failure Scenario Definition)
실패가 발생할 수 있는 주요 접점(File Path, Data Format 등)에 대한 구체적인 실패 시나리오를 정의합니다.

1.  **파일 경로 실패 시나리오:**
    *   API 엔드포인트(`API_ENDPOINT`)가 유효하지 않거나 접근 불가능한 경우 (예: Mock API URL 오류).
    *   데이터 소스 파일(DB 연결 혹은 외부 파일)이 존재하지 않는 경우.
2.  **데이터 형식 불일치 시나리오:**
    *   수집된 데이터의 형식이 예상된 JSON/CSV 구조를 벗어나는 경우 (예: 필수 필드가 누락되거나 타입 오류 발생).
3.  **네트워크 실패 시나리오:**
    *   API 호출 중 네트워크 연결이 끊기거나 타임아웃이 발생하는 경우 (Circuit Breaker 로직 검증 포함).

### Step 2: 오류 처리 메커니즘 설계 (Error Handling Mechanism Design)
각 시나리오에 대해 `DataIngestionPipeline` 클래스 내부에 구체적인 예외 처리(`try-except`, Circuit Breaker 상태 변경, Retry Logic)를 삽입하는 로직을 설계합니다.

*   **목표:** 시스템이 실패하더라도 데이터 손실을 최소화하고, 오류 상태를 명확하게 로그로 기록하며, 재시도(Retry) 메커니즘을 통해 복구할 수 있도록 보장합니다.

### Step 3: 검증 루프 실행 (Verification Loop Execution)
Step 2에서 설계된 로직을 기반으로 실제 실패 시나리오를 모방하여 코드를 테스트하고 결과(MTTR 로그 및 손실 비용 분석 데이터)를 수집하는 자동화된 루프를 실행합니다.
