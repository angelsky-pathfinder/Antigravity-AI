## 1. 디자인 시스템 요약 (Design System Summary)

| 요소 | 정의 | 값/코드 | 비고 |
| :--- | :--- | :--- | :--- |
| **배경색 (Base)** | 시스템 안정성 및 심층성을 표현 | Deep Navy ($\#0A0A2A$) | 시스템 안정성($S$)의 기반 색상 |
| **강조색 (Accent)** | 수익 지표 및 핵심 상태 강조 | Gold Accent ($\#FFD700$) | $SWRI$와 중요 알림에 사용 |
| **보조색 (Secondary)** | 데이터 상태 구분 | Crimson Red ($\#DC143C$) | 위험/경고 상태 표시 |
| **타이포그래피** | 전문성과 명확성 확보 | Sans-serif 계열 (예: Inter 또는 Roboto) | 데이터 가독성 최우선 |

## 2. 레이아웃 및 구조 (Layout & Structure)

### 2.1. 대시보드 전체 레이아웃
*   **전체 테마:** 다크 모드(Dark Mode) 기반으로, Deep Navy 배경에 Gold Accent를 사용하여 고급스럽고 안정적인 느낌을 유지합니다.
*   **구조:** 좌측 또는 상단에 핵심 지표($S$, $SWRI$)를 고정 배치하고, 중앙 및 우측에 상세 데이터와 동적 애니메이션 영역을 배치합니다.

### 2.2. 핵심 지표 섹션 (KPI Dashboard)
각 KPI는 명확한 상태(Status) 표시가 필수입니다.

*   **시스템 안정성 ($S$):**
    *   **표시 방식:** 원형 게이지 또는 상태 바(Progress Bar).
    *   **색상 매핑:** $S$ 값이 높을수록 **Gold Accent**를 점진적으로 증가시키며, 임계점(Threshold)에 도달하면 경고 색상으로 전환.
    *   **상태 표현:** '안정' (Green/Gold), '주의' (Yellow/Amber), '위험' (Red).
*   **수익 지표 ($SWRI$):**
    *   **표시 방식:** 선 그래프(Line Chart)와 실시간 수치 표시.
    *   **색상 매핑:** $SWRI$의 추세에 따라 **Gold Accent**를 사용하며, 하락 또는 위험 신호 발생 시 **Crimson Red**으로 즉각 전환하여 사용자에게 경고합니다.

## 3. 데이터 시각화 상세 사양 (Data Visualization Details)

### 3.1. Tier별 비주얼 매핑 테이블 구현
이 테이블은 사용자가 선택한 가격 티어(Standard, Premium 등)에 따라 $S$와 $SWRI$의 목표치 및 현재 상태를 비교하도록 설계합니다.

*   **구조:** 행(Row)은 각 Tier($A/B/C$)을 나타내고, 열(Column)은 $S$, $SWRI$, **Blueprint Alignment (핵심 지표 충족도)**로 구성됩니다.
*   **시각화:** 각 티어는 배경색이나 테두리 색상으로 구분하며, 목표치 대비 현재 상태를 시각적 거리감으로 표현합니다.

### 3.2. 상태 변화 애니메이션 가이드라인 (Transition Animation Guidelines)
시스템 상태가 변할 때 발생하는 동적 변화는 사용자의 인지 부하를 최소화하면서 정보를 명확하게 전달해야 합니다.

*   **상태 변경:** 데이터 포인트($S$, $SWRI$)가 업데이트될 때, 해당 값의 **색상 변화**와 **게이지/차트의 애니메이션 전환**을 동기화합니다.
    *   예시: $S$가 '주의' 상태에서 '안정' 상태로 변경 시, 게이지는 **Amber $\rightarrow$ Gold**로 부드럽게 전환되어야 합니다.
*   **경고 표시:** $SWRI$가 위험 임계치(Critical Threshold)에 도달하면, 해당 섹션 전체 배경이 순간적으로 **Crimson Red**으로 플래시(Flash)되거나 깜박이는 애니메이션을 적용하여 즉각적인 주의를 환기합니다.

## 4. API 연동 및 데이터 흐름 (API Integration Flow)

개발팀은 다음의 API 응답에 따라 시각화 요소가 어떻게 변화해야 하는지에 대한 명확한 규칙을 수립해야 합니다.

1.  **`system_status` 엔드포인트:** $S$ 값(0-100%) 및 현재 Circuit Breaker 상태를 반환. $\rightarrow$ **게이지 및 기본 배경 색상 제어.**
2.  **`revenue_metrics` 엔드포인트:** $SWRI$ 값 및 추세 데이터($t_{n-1}, t_{n-2}$). $\rightarrow$ **선 그래프의 궤적 및 색상 변화 제어.**
3.  **API 명세 기반 매핑:** 개발팀은 이 사양을 바탕으로 각 API 응답 필드와 프론트엔드 컴포넌트 간의 1:1 매핑 로직을 정의해야 합니다.
