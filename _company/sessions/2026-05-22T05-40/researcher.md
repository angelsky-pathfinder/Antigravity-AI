## 시스템 안정성($S$) 및 수익 지표($SWRI$) 관련 사용자 행동 패턴 분석 및 데이터 구조 정의

CEO의 지시사항에 따라, Instagram 및 YouTube 행동 로그에서 시스템 안정성($S$)과 수익 지표($SWRI$)에 영향을 미치는 핵심 사용자 행동 패턴을 분석하고, 시계열 플롯 초기 데이터를 준비하기 위해 필요한 데이터 구조와 측정 기준을 정의합니다.

---

### 1. 핵심 목표 재확인 및 변수 정의

우리의 궁극적인 목표는 **시스템 안정성($S$)과 수익 지표($SWRI$)를 사용자 행동 로그와 명확하게 연결**하고, 이 관계를 시계열로 시각화하는 것입니다.

*   **종속 변수 (Outputs):**
    *   시스템 안정성 ($S$)
    *   수익 지표 ($SWRI$)
*   **독립 변수 (Inputs / Behavioral Drivers):**
    *   사용자 행동 로그 (Instagram/YouTube)
    *   시장 데이터 (경쟁사 가격 변동 등)

### 2. 핵심 사용자 행동 패턴 분석 (Hypotheses & Mapping)

로그 데이터($action\_logs$)와 시장 데이터($market\_data$)를 기반으로, $S$와 $SWRI$에 영향을 미치는 잠재적인 행동 패턴을 다음과 같이 가설 설정하고 매핑합니다.

| 행동 유형 (Behavioral Factor) | 관련 로그 소스 | 예상 영향 변수 ($S$/$SWRI$) | 핵심 상관관계 가정 |
| :--- | :--- | :--- | :--- |
| **참여 깊이 (Engagement Depth)** | Instagram/YouTube 시청 지속률, 댓글 수 | $S$ (인지 부하), $SWRI$ (콘텐츠 소비 효율) | 높은 참여 깊이는 집중도를 높여 안정성을 저해하거나 수익 기회를 증대시킴. |
| **트래픽 변동성 (Traffic Volatility)** | 일별/시간별 유입 트래픽 변화량 | $S$ (서버 부하), $SWRI$ (잠재 매출) | 급격한 트래픽 증가는 시스템 안정성에 즉각적인 스트레스를 가함. |
| **행동 전환율 (Action Conversion)** | CTA 클릭 수, 특정 콘텐츠 소비 후 행동 로그 | $SWRI$ (수익화 효율) | 사용자가 실제 구매/행동으로 이어지는 과정의 마찰 감소가 수익 지표에 긍정적 영향을 미침. |
| **시장 민감도 (Market Sensitivity)** | 경쟁사 가격 변동 데이터 | $S$ (경쟁 압박), $SWRI$ (가격 전략) | 시장 변동성이 클수록 시스템이 외부 충격에 더 취약해짐. |

### 3. 필요한 데이터 구조 및 측정 기준 정의

시계열 플롯을 준비하기 위해, 행동 로그와 시스템 지표를 통합할 수 있는 최종 데이터 구조($Schema$)가 필요합니다. 이는 기존에 정의된 `action_logs.schema`와 `market_data.schema`를 확장하여 구성되어야 합니다.

#### 3.1. 필수 데이터 필드 요구사항 (Data Structure Requirements)

**A. 행동 로그 테이블 (`action_logs`) 확장 시:**

| 필드명 | 데이터 타입 | 설명 | $S$/$SWRI$ 기여도 | 측정 기준 |
| :--- | :--- | :--- | :--- | :--- |
| `timestamp` | DateTime | 이벤트 발생 시점 (시계열 축) | 높음 | UTC 기준, 정밀 시간 |
| `platform` | String | Instagram 또는 YouTube 구분 | 중간 | 분류 기준 |
| `metric_type` | Enum | 행동 유형 (예: ViewDuration, ClickThroughRate, CommentCount, ConversionAction) | 높음 | 측정 대상 정의 |
| `value` | Float/Integer | 실제 측정된 값 | 높음 | Raw Data |
| `system_load_proxy` | Float | 해당 이벤트 발생 시점의 시스템 내부 부하 지표 (추정치 또는 실제 로그 연동) | 매우 높음 ($S$) | 백엔드 $S$와의 동기화 필요 |
| `contextual_market_factor` | Float | 해당 시점의 외부 시장 변수 값 (예: 경쟁사 가격 변화율) | 중간 ($SWRI$) | $SWRI$ 분석을 위한 외부 변수 |

**B. 시장 데이터 테이블 (`market_data`) 확장 시:**

| 필드명 | 데이터 타입 | 설명 | $S$/$SWRI$ 기여도 | 측정 기준 |
| :--- | :--- | :--- | :--- | :--- |
| `timestamp` | DateTime | 시장 변동 발생 시점 (시계열 축) | 높음 | UTC 기준, 정밀 시간 |
| `competitor_price_change` | Float | 핵심 경쟁사의 가격 변화율 (%) | $SWRI$ | % 변화 값 |
| `market_volatility_index` | Float | 해당 기간의 시장 변동성 지표 (VIX 등 추정치) | $S$/$SWRI$ | 표준편차 또는 특정 지수 |

#### 3.2. 시계열 데이터 준비 기준 (Measurement Criteria)

1.  **시간 정렬 (Temporal Alignment):** 모든 행동 로그와 시장 데이터는 **동일한 시간 해상도(예: 일별, 시간별)**로 정렬되어야 합니다. $S$와 $SWRI$의 변화를 정확히 포착하기 위해 이벤트 발생 시점과 지표 측정 시점을 엄격하게 동기화해야 합니다.
2.  **노이즈 필터링 (Noise Filtering):** 행동 로그의 경우, 단순 클릭이나 무의미한 상호작용은 제외하고 **실질적인 '깊은 참여' 또는 '전환 행동'**만을 $S$와 $SWRI$에 기여하는 주요 변수로 정의하여 필터링해야 합니다.
3.  **상관관계 계산 프레임워크:** 데이터 수집 후, 각 행동 지표($X$)가 $S$와 $SWRI$의 변화율($\Delta S, \Delta SWRI$)과 어떤 **선형/비선형 상관관계**를 가지는지 측정하는 분석 프레임워크를 즉시 적용해야 합니다.

### 4. 최종 권고 사항 (Action Plan)

1.  **데이터 계약(Contract) 확정:** `action_logs.schema`와 `market_data.schema`를 위의 요구사항에 맞춰 **최종적으로 업데이트**하고, 백엔드 API 명세($FSD$) 구현 준비를 완료합니다.
2.  **시스템 연동 정의:** 행동 로그의 특정 이벤트가 시스템 안정성 지표($S$)에 미치는 **인과 관계 함수(Causal Function)**를 백엔드 로직 내부에 명확히 정의하도록 코다리에게 요청합니다.
3.  **시계열 초기 데이터 생성:** 확보된 스키마를 기반으로, 최소 7일간의 행동 로그와 시장 데이터를 결합하여 $S$ 및 $SWRI$의 **초기 시계열 플롯 데이터 세트**를 생성하는 작업을 다음 단계에서 진행합니다.
