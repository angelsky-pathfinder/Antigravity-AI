## 🎯 핵심 가설 (Hypothesis)

**가설:** 손실 회피 심리를 극대화하여 시각적 긴장감(Tension)을 유도하는 랜딩 페이지 디자인 요소(색상, 프레이밍, 메시지 강도)를 적용할 경우, 단순한 이득 제시 모델보다 **Tension-to-Action Conversion Rate**가 통계적으로 유의미하게 증가할 것이다.

*   **Null Hypothesis ($H_0$):** 시각적 긴장감(손실 회피 프레임워크)을 적용하는 것은 행동 유도에 아무런 영향을 미치지 않는다.
*   **Alternative Hypothesis ($H_a$):** 손실 회피를 기반으로 한 시각적 긴장감 설계는 표준 모델 대비 T-A Conversion Rate를 높인다.

## 🔬 검증을 위한 최소 요구사항 및 측정 지표 정의 (PoC 설계)

이 가설을 검증하기 위해, 변수(독립 변수)와 결과(종속 변수)를 명확히 분리하고 실험 환경을 설정해야 합니다.

### 1. 독립 변수 (Independent Variables: Tension Induction Factors)

실험의 핵심은 '긴장감'을 유도하는 디자인 요소를 조작하는 것입니다. 최소 3가지 이상의 비교 그룹(A/B 테스트 그룹)을 설계합니다.

| 변수 | 설명 | 레벨/조작 방식 | 목표 효과 (Tension Source) |
| :--- | :--- | :--- | :--- |
| **V1: 색상 팔레트** | 사용되는 주된 배경 및 강조 색상 | 딥 블루 (안정감 기반), 크림슨 레드 (긴급성/손실 경고) | 심리적 위험 신호 부여 |
| **V2: 프레이밍 메시지** | 헤드라인 및 CTA 주변의 문구 구조 | 이득 중심 ("얻게 될 것") vs. 손실 중심 ("잃게 될 기회") | 손실 회피 극대화 |
| **V3: 시각적 긴장감 강도** | 디자인 요소의 밀도 및 대비 (Contrast) | 낮은 대비/낮은 밀도 (안정적) vs. 높은 대비/높은 밀도 (긴급함) | 행동 유도 압박 부여 |

### 2. 종속 변수 (Dependent Variable: Measurement KPI)

측정하고자 하는 핵심 지표는 **Tension-to-Action Conversion Rate**입니다.

$$\text{T-A Conversion Rate} = \frac{\text{실제 행동 발생 수}}{\text{노출된 사용자 수}} \times 100$$

*   **핵심 지표:** **Conversion Rate (CR)**: 특정 CTA 클릭 또는 가입 완료율.
*   **보조 지표:**
    *   **Time-on-Page (ToP):** 사용자가 긴장감을 느끼며 페이지에 머무는 시간. (긴장감이 충분히 유발되었는지 측정)
    *   **Bounce Rate:** 높은 긴장감으로 인해 이탈이 발생했는지 확인.

### 3. 최소 요구사항 및 실험 설계 단계

| 단계 | 요구사항 | 세부 실행 내용 | 책임 에이전트 |
| :--- | :--- | :--- | :--- |
| **Phase 1: 정의** | 최종 디자인 변수 확정 | V1, V2, V3 중 가장 효과적일 것으로 예상되는 조합(예: 크림슨 레드 + 손실 프레이밍)을 초기 가설로 설정. | Designer / Business |
| **Phase 2: 구현 (A/B Test)** | 실험 환경 구축 | 최소 2가지 이상의 대조 그룹(Control vs. Treatment)을 포함하는 A/B 테스트 가능한 랜딩 페이지 초안 제작. | Designer / Instagram |
| **Phase 3: 측정** | 데이터 수집 시스템 정의 | Google Analytics 또는 자체 트래킹 메커니즘을 통해 각 그룹별 T-A Conversion Rate를 실시간으로 집계할 수 있는 구조 설계. | 코다리 / Business |

## 🚀 Tension-to-Action Conversion Rate 측정 시스템 실행 계획 (Phase 1: Measurement Pipeline Design)

### 🎯 목표

### ⚙️ 핵심 지표 정의 (KPI Definition)
측정하고자 하는 최종 KPI는 **Tension-to-Action Conversion Rate ($\text{T2A CR}$)** 입니다.

$$\text{T2A CR} = \frac{\text{실제 행동 전환 수}}{\text{심리적 긴장감 유도 노출 수}}$$

*   **A. 긴장감 유도 데이터 ($\text{Tension Input}$):** 랜딩 페이지 디자인, 카피라이팅(Loss Aversion 요소), 시각적 팔레트(Blue/Red) 적용 상태를 정량화하여 기록한다. (Source: Designer 산출물, Writer 지침서)
*   **B. 행동 데이터 ($\text{Action Output}$):** 랜딩 페이지 방문 후 특정 CTA 클릭, 문의 양식 제출, 또는 최종 전환 완료와 같은 구체적인 사용자 상호작용 이벤트를 로그로 기록한다. (Source: 웹 분석 툴, 서버 로그)

#### Step 2: 측정 메커니즘 설계 (Measurement Mechanism Design)
**목표**: A와 B 데이터를 연결하여 $\text{T2A CR}$을 계산할 수 있는 데이터 구조를 정의한다.

## Tension-to-Action Conversion Rate ($\text{T2A CR}$) 측정 데이터 흐름 및 목표 매핑 계획

### 2. 데이터 흐름 및 연결 로직 (The Flow)

데이터는 '심리적 설정'에서 시작하여 '행동 결과'로 수렴하는 단방향의 인과 관계를 가집니다.

**단계 1: $\text{Session\_Tension}$ 설정 (Input Layer)**
*   **출발점:** 랜딩 페이지 디자인 및 콘텐츠 전략 ($\text{designer.md}$, $\text{youtube.md}$ 등에서 정의된 심리적 긴장감 수준).
*   **기능:** 사용자가 특정 세션에 진입할 때, 시스템은 해당 세션의 초기 맥락(Tension Level)을 기록합니다.
    *   $\text{Session\_Tension} = f(\text{Content Framing}, \text{Visual Stress})$

**단계 2: $\text{Action\_Log}$ 기록 (Process Layer)**
*   **연결:** 사용자가 $\text{Session\_Tension}$ 상태에서 특정 행동(예: 구매 버튼 클릭, 리드메일 제출)을 수행하면, 이 행동은 $\text{Action\_Log}$에 타임스탬프와 함께 기록됩니다.
    *   $\text{Action\_Log} = \{ \text{Session ID}, \text{Timestamp}, \text{Action Type}, \text{Value}\}$

**단계 3: $\text{T2A CR}$ 계산 (Output Layer)**
*   **계산:** 시스템은 특정 시간 내에 기록된 모든 세션(Session)과 그 안의 행동 로그(Action\_Log)를 비교하여, **특정 $\text{Session\_Tension}$ 레벨을 가진 사용자들이 어떤 종류의 $\text{Action}$을 수행했는지** 집계합니다.
    *   $$\text{T2A CR} = \frac{\text{Actions performed by sessions with Tension Level } T}{\text{Total sessions with Tension Level } T}$$

# T2A CR 측정 데이터베이스 스키마 설계

이 스키마는 Tension-to-Action Conversion Rate ($\text{T2A CR}$) 측정을 위한 핵심 엔티티인 심리적 상태와 실제 행동 로그를 관리합니다.

## 1. Session_Tension 테이블 (심리적 상태 기록)
사용자가 특정 시점에 경험한 심리적 긴장감(Tension) 수준을 기록합니다. 이는 행동 유도 콘텐츠의 '입력' 변수 역할을 합니다.

| 필드명 | 데이터 타입 | 제약 조건 | 설명 |
| :--- | :--- | :--- | :--- |
| `session_id` | UUID | PK, Not Null | 세션 고유 식별자 |
| `user_id` | UUID | FK (User Table) | 사용자 ID |
| `timestamp` | Timestamp | Not Null | 긴장감 측정 시점 |
| `tension_score` | Float | Not Null | 측정된 심리적 긴장감 점수 (0.0 ~ 10.0) |
| `context` | JSONB | | 해당 상태를 유발한 맥락 정보 (예: 'Pricing Page View', 'Feature Comparison') |
| `session_type` | Enum | Not Null | 세션 유형 (예: 'LandingPage', 'VideoAd', 'FormFill') |

## 2. Action_Log 테이블 (행동 로그 기록)
사용자가 취한 실제 행동을 기록합니다. 이는 결과 변수 역할을 하며, $\text{T2A CR}$ 계산의 분모 및 분자를 구성합니다.

| 필드명 | 데이터 타입 | 제약 조건 | 설명 |
| :--- | :--- | :--- | :--- |
| `action_id` | UUID | PK, Not Null | 행동 로그 고유 식별자 |
| `user_id` | UUID | FK (User Table) | 사용자 ID |
| `timestamp` | Timestamp | Not Null | 행동 발생 시점 |
| `action_type` | Enum | Not Null | 수행된 행동 유형 (예: 'CTA Click', 'Form Submission', 'Scroll_Deep') |
| `target_session_id` | UUID | FK (Session_Tension) | 해당 행동이 참조하는 심리적 세션 ID |
| `outcome` | Enum | Not Null | 행동 결과 (예: 'Success', 'Failure', 'NoAction') |
| `action_details` | JSONB | | 행동에 대한 상세 정보 (예: 클릭한 버튼 ID, 입력된 값) |

**데이터베이스 관계:**
*   $\text{Session\_Tension} \rightarrow 1 : N \rightarrow \text{Action\_Log}$ (하나의 심리적 상태는 여러 행동 로그로 이어질 수 있음)

### 2. API 엔드포인트 명세 ($\text{POST /api/track\_action}$)

이 엔드포인트는 사용자의 실제 행동을 기록하고, 시스템이 $\text{T2A CR}$ 계산에 필요한 데이터를 확보하도록 설계합니다.

**엔드포인트:** `POST /api/track_action`
**목적:** 사용자 행동 로그를 시스템에 기록하여 $\text{T2A CR}$ 측정 데이터 파이프라인에 입력.
**인증:** JWT (사용자 인증 필요)

#### Request Body (요청 본문)

```json
{
  "user_id": "UUID",
  "action_type": "string",         // 수행된 행동 유형 (예: 'CTA Click', 'Form Submission')
  "target_session_id": "UUID",    // 연결될 Session_Tension ID
  "outcome": "string",            // 행동 결과 (예: 'Success', 'Failure')
  "action_details": {              // 행동에 대한 상세 정보
    "element_id": "string",        // 클릭된 요소의 ID 또는 경로
    "value_submitted": "string"   // 입력된 값 (필요한 경우)
  }
}
```

#### Response Body (응답 본문)

성공적으로 로그가 기록되었음을 확인합니다.

```json
{
  "status": "success",
  "message": "Action successfully logged.",
  "action_id": "UUID"
}
```

핵심 전략은 **'손실(Loss)'의 심리적 무게를 시각적 대비와 레이아웃의 비대칭성을 통해 극대화**하고, **'행동(Action)'으로의 전환 경로를 크림슨 레드 색상으로 집중 유도**하는 것입니다.

#### 1. 컬러 팔레트 및 긴장감 매핑 (Color & Tension Mapping)

| 요소 | 역할/심리 | 색상 코드 (HEX) | 적용 전략 |

| **섹션 대비 (Contrast)** | **High Tension** ($\text{Tension} > 70\%$) | 배경(Deep Blue)과 강조색(Crimson Red)의 명도/채도 대비를 극대화하여 시각적 충돌 유도. | 즉각적인 주의 집중 및 위험 인식 증폭. |

실제 디자인 단계에서 적용할 구체적인 변수는 다음과 같습니다:

1.  **$\text{Tension}$ 기반 섹션 분리:** $\text{Session\_Tension}$ 값이 높은 영역(예: 리스크 설명, 문제 정의)은 **Deep Blue 배경 위에 Crimson Red의 얇은 오버레이 레이어**를 적용하여 시각적 긴장감을 즉시 부여합니다.
2.  **CTA 색상 통일:** 모든 CTA 버튼(`Button` component)은 **`#DC2626` (Crimson Red)**로 고정하며, 마우스 호버(Hover) 시에는 명도가 약간 낮아지거나 대비가 강해지는 효과를 주어 즉각적인 반응을 유도합니다.
3.  **데이터 시각화:** $\text{Action\_Log}$의 흐름에 따라 각 섹션 간의 **수직 여백(Padding)**을 조절합니다. 긴장감이 높은 곳은 좁고 밀집하게, 행동 유도 직전에는 충분한 여백을 두어 다음 단계로 넘어가기 전 심리적 '호흡' 공간을 제공합니다.
4.  **비주얼 대비:** Deep Blue 배경에서 Crimson Red 강조색이 **최소 $3:1$ 이상의 명도 대비**를 갖도록 설계하여, 시각적 위계가 혼란스럽지 않고 명확하게 작동하도록 보장합니다.

>
> **✅ 재작성 후크:** **"당신이 이 기회를 놓치고 있다면, 당신의 경쟁자는 이미 앞서가고 있습니다. 지금 멈추면, 그 격차는 따라잡기 힘들 겁니다."**

>
> **✅ 재작성 후크:** **"당신의 비즈니스에서 낭비되는 시간과 자원은 매일 비용입니다. 이대로 방치하면, 당신은 눈에 보이지 않는 '숨겨진 손실'을 계속해서 감수하게 될 겁니다."**
>
> *   **심리적 효과:** 현재의 비효율(낭비)이 미래에 누적될 잠재적 금전적/시간적 비용으로 연결됨을 제시하여, 행동하지 않았을 때 발생하는 '숨겨진 손실'에 대한 두려움을 자극합니다.
