# 데이터 시각화 요구사항 정의 (S vs SWRI)

## 1. 목표 및 전략 재확인
**목표:** 시스템 안정성($S$)과 수익 지표($SWRI$)의 인과관계를 시각화하여, 리스크 기반 가격 책정 모델의 논리적 근거와 신뢰를 확보한다.

## 2. 데이터 요구사항 (Layered Data Specification)

### Layer 1: 시스템 안정성 ($S$) 측정 기준
*   **지표:** API 응답 성공률 (Success Rate), 95th/99th Percentile Latency, 치명적 에러 발생 빈도 (Fatal Error Frequency).
*   **시각화 역할:** 시스템의 **실시간 '건강 상태'** 및 **변동성**.

### Layer 2: 수익 지표 ($SWRI$) 측정 기준
*   **지표:** 시간 기반 순매출($SWRI$), 안정성 레벨별 예상 매출 변화율, 프리미엄 옵션 전환율.
*   **시각화 역할:** 시스템 상태에 따른 **'비즈니스 성과'**.

### Layer 3: 관계 및 통제 지표 (핵심 메시지)
*   **지표:** $S \rightarrow SWRI$ 상관관계 맵, 최적 운영 영역(Optimal Operating Zone).
*   **시각화 역할:** **인과관계 증명** 및 **최적의 의사결정 기준 제시**.

## 3. 개발/디자인 지침 (Actionable Specification)
*   **개발팀 지침:** Layer 1 데이터는 실시간 스트리밍을 통해 $S$ 값으로 변환되어야 하며, Layer 2 데이터는 $S$ 값 변화에 따른 예측 모델(Risk-Weighted Revenue)로 계산되어야 한다.
*   **디자인팀 지침:** 시각화는 'Resilience 강조형' 카피와 색상 대비 규칙을 최우선으로 반영하며, 특히 $S_{low}$ 구간에서 발생하는 $SWRI$의 급격한 하락(위험)을 명확하게 대비시켜야 한다.
